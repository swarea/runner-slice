## Defects found on the real host, and fixed

Each fix landed with a drill case that fails without it.

1. **The release archive unpacked group-writable**, and root's preflight
   refused it (#16).
2. **`systemctl show` prints `RestrictNamespaces=yes`, not an empty value.**
   A correct host would have failed its own check (#17).
3. **The printed registration used `--replace`**, which silently takes over
   another host's runner of the same name (#17).
4. **`config.sh` checks its libraries by `./bin` paths before it changes
   directory.** Run from elsewhere, the check passed vacuously, with `ldd: …
   No such file` (#17, `env -C`; actions/runner #945 and #4460).
5. **`config.sh remove` rejects `--unattended`** (#17).

## Follow-up: the post-acceptance review (#18), 2026-10-16

The same VM, after the acceptance had ended and the host matched its
baseline. Commit 7f84c01 (tree ae6c64a) was installed. All 49 files in the
archive were compared with the commit and are identical; root owns the whole
tree. No runner was registered. Every case used a new test-only profile,
`probe`, which was never registered, and new test-only objects. Every
temporary host change was undone. Afterwards, `/etc/passwd`, `/etc/group`
and `/etc/login.defs` matched their checksums from before, byte for byte,
and the host listing matched its state from before.

| Case | Observed |
|---|---|
| Preflight on systemd 255 | `ok systemd 255`. No "unverified" warning, because 255 is the supported version. |
| The runner directory during the unpack | 232 samples, in this order: 750 (created by apply), then 700 (for the whole unpack), then 750 (after chmod). The archive's 0775 never appeared. |
| A symlinked `bin/` in the runner directory | `check`: `cannot determine the installed runner version`. With the real `bin/`: `runner version 2.338.0`. |
| A real process running as the account (`Uid: 997 997 997 997`) | `retire` refused, named the pid, and removed nothing. |
| A process holding the account only as its saved uid (`Uid: 0 0 997 0`) | `pgrep -u`, the old check, found nothing (exit 1). `retire` refused, named the pid, and removed nothing. |
| `userdel` failing, with `/etc/passwd` locked | `userdel could not remove rs-probe (exit 1); the account is still there`. The account, group, home, runtime root, marker and unit were all still there. |
| The account removed, but an immutable file in the runtime root | `could not remove all of /var/lib/rs-probe`. The unit and the marker were kept. After `chattr -i`, the next `retire` removed the root, then the unit, and exited 0. |
| `USERGROUPS_ENAB no` | `userdel` left the group. RunnerSlice removed it as the account's own unused group (gid 987). Exit 0. |
| The group with a member, and a home not owned by the account | `userdel` exited 12. The leftover home was reported, and not removed. The group was left, because it has a member. Exit 1. On a second run, both were reported again. The group was now "without its account", and was still not removed. After a manual cleanup, as the recovery table describes, `retire` exited 0. |

An independent review of 7f84c01 then found that retirement could empty a
filesystem mounted in the runtime root. The fix and its follow-up, 90f7ec8
(tree 84a0cec, which became `main`), were installed on the same VM, again
with all 49 files compared with the commit:

| Case | Observed |
|---|---|
| A tmpfs mounted at `/var/lib/rs-probe/work`, holding a file | `retire` exited 1: `a filesystem is mounted at or below /var/lib/rs-probe`. Nothing was removed. The file on the mount, the account and the marker were all still there. |
| The same, after `umount` | `retire` removed the account, the root and the unit, and exited 0. Nothing of the probe was left. `/etc/passwd`, `/etc/group` and `/etc/login.defs` matched their checksums from before. |

The drills inside the VM ran as `nobody`: 545 cases, 0 failed.
